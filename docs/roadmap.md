## Phase 6: 入力補助

### Status

Implemented - Version 1.3 release candidate

### Scope

- OCRによる入力補助
- 過去入力からの候補表示
- 勤務先別のよく使う収入区分
- 添付書類からの半自動登録

### Initial Experiment Scope

- PDFまたは画像を添付した給与明細新規登録で、端末内OCRを実行する
- 支給年月、勤務先、額面、手取り、控除合計の候補を抽出する
- 読み取り候補は給与明細入力フォームへ自動入力するが、自動保存しない
- ユーザーは通常の入力フォームで原本と照合し、修正して保存する
- OCR画像、PDF、認識テキストを外部サーバーへ送信しない
- TestFlightで実機検証し、精度と入力体験が不十分であればNo Goとして戻す

### Implementation Stages

1. 主要3項目のOCR精度改善
   - PDF埋め込み文字の直接抽出
   - 写真・スキャンPDFの位置ベース解析
   - 候補の確からしさと原本確認
   - 総支給額、振込額、控除合計の整合性確認
2. 勤務先別の控除項目
   - 所得税、住民税は共通固定項目として維持
   - その他の控除は大分類を設けず、勤務先ごとの表示名とOCR用別名で管理
   - 勤務先ごとの表示・非表示、追加、名称変更、並べ替え
   - 既存の社会保険料は明細編集時に段階的に勤務先固有項目へ移行
3. 控除内訳OCRと推移
   - OCRラベルを勤務先の控除項目へ対応づける
   - 不明なラベルを新規項目候補として提示する
   - 勤務先別に控除合計と各控除項目の月別推移を表示する

段階2と、段階3のうちOCRラベル対応・新規項目候補は実装済み。写真、写真ライブラリ、PDFからの端末内OCRとフォームへの自動入力は実機検証済み。控除項目の月別推移は今後の検討対象とする。

### Completion Criteria

- OCRはフォームへの自動入力として提供するが、給与明細を自動保存しない
- ユーザーが確認、修正して保存する
- 誤認識時の修正がしやすい
- 低信頼候補や推定候補を含む場合は、入力フォーム内で要確認と案内する
- 金額が整合しない場合は保存前に差額を示し、修正またはユーザー判断での保存を選べる
- 未入力と0円を区別できる
